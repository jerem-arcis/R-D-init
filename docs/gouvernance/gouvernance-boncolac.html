00 · Le principe

Un produit, cinq étapes, plusieurs mains

L'application sert à créer un nouveau produit dans SAP. Elle ne couvre pas tout le cycle : la partie amont (rédaction de la DE, import beCPG, génération du code PJ, validation Codir) se passe hors application (dans beCPG). L'app prend le relais à partir de la validation Codir : un flux quotidien importe les projets validés, l'ADV crée le code chapeau, puis quatre services remplissent la Fiche de Lancement avant l'envoi à SAP.

Amont · hors app

DE + validation Codir

Dans beCPG : le Commerce/Marketing rédige la DE, import beCPG + code PJ, puis le Codir valide.

Étape 1

Import + code chapeau

Un flux quotidien importe les projets validés Codir ; l'ADV crée le code chapeau et l'envoie à SAP.

Étape 2

Validation DL (auto)

Un flux met à jour le statut du projet selon que la validation DL est passée ou non. Aucune saisie.

Étape 3

Les visas

Commerce/Marketing, R&D, ADV, Qualité remplissent chacun leur section et la « visent ».

Étape 4

Création SAP

Les 4 visas posés → l'article est créé ; mails services + entrepôt (palettisation).

✓ Compris le 16/09/2026 (Atelier 4, cycle de vie DE)
  • L'app démarre à la validation Codir : tout l'amont (DE, import beCPG, code PJ, validation Codir) est hors app. Un flux quotidien importe dans Dataverse les projets validés Codir puis lance l'alerte ADV.
  • De « en attente de code chapeau » jusqu'à « en attente de DL » : seul l'ADV crée / modifie ; les autres secteurs sont en lecture seule.
  • La validation DL n'a plus d'import manuel : un flux Power Automate met à jour le statut automatiquement (passée ou non).
  • Fiche de Lancement : quatre secteurs : Commerce/Marketing, R&D, ADV, Qualité. Une fois les visas signés (sections remplies), l'envoi SAP est possible.
  • L'Entrepôt est informé en fin de cycle (données de palettisation).
⚠ Zones non définies / écart avec le code

DS (négoce) : circuit non défini pour l'instant, volontairement laissé vide. Écart app ↔ cible : l'app possède encore un écran de création de DE et des visas ADV / Industriel / Commerce (sans section R&D ni Qualité). L'alignement sur ce schéma reste à implémenter côté code.

⚠ À savoir

Aujourd'hui l'application ne bloque personne par rôle : tout utilisateur connecté peut tout faire (y compris ouvrir l'Admin). Ce document décrit la cible ; les groupes de sécurité sont ce qui la rendra réellement applicable.

01 · RACI

Matrice de responsabilité

Qui a le droit de faire quoi dans l'application, une fois le projet importé (après la validation Codir). Cinq acteurs agissent dans l'app ; la validation Codir, la validation DL et l'entrepôt sont hors app (voir l'encart en dessous).

ADV

ADV / Supply Chain

Seul acteur de la phase code chapeau → DL : crée/modifie la demande, crée le code chapeau, envoie à SAP. En FL : saisit/vise la section ADV et déclenche « Créer dans SAP ».

COM

Commerce / Marketing

Rédige la DE en amont dans beCPG (hors app). Dans l'app : saisit/vise le volet commercial de la FL (libellés, origine, canaux, hiérarchie, marque, nomenclature, sites, GTIN).

R&D

R&D

Dans l'app : remplit et vise sa section de la FL (étude / recette produit). Lecture seule sur le reste.

QUA

Qualité

Dans l'app : remplit et vise sa section de la FL (conformité, spécifications). Lecture seule sur le reste.

ADM

Admin / IT

Page Admin : listes déroulantes, registre des flux, journal des erreurs SAP, gestion des droits (à venir).

Hors application (contexte)
  • Codir : valide le projet en amont dans beCPG. L'app ne fait que récupérer le statut via un flux quotidien qui crée le projet dans Dataverse.
  • Validation DL : plus d'étape manuelle, un flux met à jour le statut du projet (passée / non passée). Aucun rôle applicatif.
  • Entrepôt : informé en fin de cycle, reçoit le mail « données de palettisation » après la création SAP. Pas de saisie.

02 · Entra ID & M365

Groupes de sécurité & listes de diffusion

Deux besoins à ne pas confondre : les groupes de sécurité décident qui peut faire quoi dans l'app ; les listes de diffusion décident qui reçoit quelle alerte envoyée par les flux.

Groupes de sécurité

Convention : SEC-BONCOLAC-<Rôle>. Un utilisateur peut appartenir à plusieurs groupes.

SEC-BONCOLAC-CommerceCommerce + MarketingSaisie & visa section Commerce de la FL, sites de stockage
SEC-BONCOLAC-RDR&DSaisie & visa section R&D (à exposer côté app)

03 · Pour tous les utilisateurs

Mode opératoire, expliqué très simplement

Écran par écran, ce qu'on fait et où cliquer. Les captures correspondantes sont dans docs/modop/img/.

1

L'accueil (tableau de bord) 🏠

01-dashboard.png

La page d'entrée montre les produits en retard (rouge), bientôt à lancer (orange), et un calendrier.

👉 Tu regardes le rouge. S'il y en a, tu cliques dessus pour voir ce qui bloque.

2

La liste des demandes 📋

02-demandes-etude.png

Toutes les DE et DS, avec des onglets de filtre (Brouillon, En attente de code chapeau, Validée…).

👉 Les DE remontent automatiquement via les flux Power Automate : pas besoin de les créer à la main. Une DS (négoce), en revanche, doit être créée avec « + Créer une DS ». Pour continuer une demande, clique sur sa ligne.

3

Créer une demande ✏️

03-creer-de.png

Le formulaire. Trois boutons clés : Récupération beCPG (remplit tout seul), Demander mon code (le code chapeau, indispensable), Envoyer vers SAP.

⚠️ Si une case obligatoire manque (souvent le poids net), « Envoyer » reste gris. Une fenêtre 🟢/🔴 confirme l'envoi. Bouton Enregistrer = brouillon.

4

L'accueil des Fiches de Lancement 🗂️

04-accueil-fl.png

Une fois la demande validée, elle devient une Fiche de Lancement. La liste est triée par urgence.

👉 Clique sur ta fiche pour remplir ta partie.

5

Remplir ta partie (fiche par service) 🧩

05-fiche-par-service.png

La fiche est coupée par équipe (Commerce, ADV, R&D, Qualité). Tu remplis seulement tes cases, puis « Viser » (= je signe). Si un souci : « Refuser » + écrire pourquoi.

⚠️ Après le visa, tes cases se verrouillent. Vérifie avant de signer. Chaque équipe travaille en même temps.

6

La fiche complète 📄

06-fiche-complete.png

Toute la fiche d'un coup. Quand les équipes ont signé, « Créer dans SAP » s'active, ça prend quelques minutes (normal).

🟢 « Article créé dans SAP » = gagné · 🔴 erreur = préviens l'admin · ⏳ « toujours en cours » = reviens plus tard. Bouton Export PDF pour imprimer/sauver.

7

Les sites de stockage 📦

07-sites-stockage.png

On coche les entrepôts où le produit sera rangé (en général, partie Commerce).

8

L'administration (réservé) 🔧

08-admin.png

Réservé à l'admin : gère les listes déroulantes et le journal des erreurs SAP. Si tu n'es pas admin, tu n'as rien à faire ici.

04 · Power Platform

Flux Power Automate : ordre & contrats

Les URL des flux vivent dans la table cr04e_fluxregistre (clé → URL) ; l'app résout par getFluxUrl(cle). En-tête Accept-Language: en-US obligatoire : sinon SAP reçoit les décimaux avec une virgule et renvoie 400.

✓ Réduction du payload DE/DS : faite

La DE et la DS n'envoient plus que { ID, PoidsNet } à SAP_SEND ; tout le reste (code chapeau, EAN, groupes SAP, ZUG…) est écrit en Dataverse par l'app puis relu par le flux. Modèle « n'envoyer que l'ID, le flux relit Dataverse ».

Flux planifiés (hors registre app)

Deux flux tournent en tâche de fond (non déclenchés par l'app, donc absents de cr04e_fluxregistre) :

  • Import quotidien Codir : récupère les derniers statuts « validation Codir » depuis beCPG ; si le projet n'est pas encore dans Dataverse, il le crée puis lance l'alerte ADV (demande de code chapeau).
  • Validation DL : met à jour le statut du projet selon que la validation DL est passée ou non (remplace l'ancien import manuel du fichier DL).
  • Synchro SAP quotidienne : met à jour les tables référentielles (listes déroulantes alimentées depuis SAP).

Ordre d'exécution

DE : Demande d'Étude
« Envoyer vers SAP »
│
├─ 1. VERIF_DE   { Numéro }                     ── BLOQUANT
│      200 → on continue    400 → STOP « code déjà existant »
│
├─ 2. Écriture Dataverse                          ── BLOQUANT
│      cr04e_projet + cr04e_divisionprojet
│      statut = dl_attente_validation_cdg
│
└─ 3. SAP_SEND   { ID, PoidsNet: "1.598" }      ── BLOQUANT
       200 → reste dl_attente_validation_cdg (au CDG de décider)
       400 → repasse de_brouillon (retry = même ligne)
DS : Demande Simplifiée (négoce)
Ouvrir la DS → saisir le code chapeau → « Envoyer vers SAP »
│
├─ 1. Écriture Dataverse (code chapeau, EAN)      ── BLOQUANT
│
└─ 2. SAP_SEND   { ID, PoidsNet }               ── BLOQUANT
       200 → statut = ds_validee (prête pour la FL)
       400 → statut inchangé (ds_attente_cc), retry possible

Pas de VERIF_DE ni de validation CDG pour la DS.
FL : Fiche de Lancement (asynchrone, polling)
DE/DS validée → visas ✓ → « Créer dans SAP »
│
├─ 1. Lire modifiedon de référence (baseline)
├─ 2. SAP_SEND_FL   { ID }                      ── non bloquant (~8s)
│
├─ 3. Polling 5s (max 10 min) : relire modifiedon + cr04e_fluxenvoiefl
│      quand modifiedon change :
│      ├─ 'reussi' → SAP_SEND_Fiche_final (mail PDF)
│      │            statut = fl_sap_cree + date d'envoi (verrou)
│      └─ 'erreur' → statut inchangé, formulaire éditable
│
└─ Timeout 10 min → modale « toujours en cours »

05 · Suivi

Décisions actées & questions ouvertes

✓ Compris le 16/09/2026 (Atelier 4)
  • L'app démarre à la validation Codir (amont hors app) ; un flux quotidien importe les projets validés dans Dataverse.
  • Phase code chapeau → DL : seul l'ADV crée / modifie ; les autres secteurs sont en lecture seule.
  • Validation DL automatique (flux Power Automate), plus d'import manuel.
  • FL : quatre secteurs (Commerce/Marketing, R&D, ADV, Qualité) ; une fois les visas posés → envoi SAP possible.
  • Entrepôt informé en fin de cycle (palettisation). Marketing fusionné dans Commerce.
⚠ Non défini / remplace le 15/09

DS (négoce) : circuit non défini, laissé vide volontairement. Cette version annule les points du 15/09 « Industriel = rôle FL » et « Qualité/R&D sans visa » : la FL cible ne comporte ni Industriel ni Gestion Besoin.

Encore à trancher

  • Écart app ↔ cible : l'app a des visas ADV/Industriel/Commerce (+ section Gestion Besoin masquée) et un écran de création de DE. Où atterrit le contenu Industriel (emballages, palette) : R&D, Qualité, ou Entrepôt ? Puis implémenter les sections R&D et Qualité et retirer la création de DE côté app.
  • Nombre de visas requis pour activer « Créer dans SAP » : cible 4 (ADV, Commerce, R&D, Qualité) ; aujourd'hui l'app en exige 3.
  • DS (négoce) : décrire le circuit (qui, quels statuts, quels flux), rien n'est documenté pour l'instant.
  • Visa de secours : autoriser un service à viser à la place d'un autre (congés / backup) ? Si oui, prévoir un rôle « superviseur ».
  • Alertes mail : temps réel (à chaque changement) ou digest quotidien ? Listes nominatives ou boîtes partagées par service ?
  • Contenu du mail Entrepôt : quelles données de palettisation exactement, et à partir de quel statut ?
