## 🔗 1. Liens profonds généralisés depuis les mails (code PJ)

Objectif : un clic dans un mail ouvre l'app **au bon endroit**, identifié par le **code PJ**
(`cr04e_codeprojet`), résolu en fiche côté app.

- **`src/lib/deepLinkRoutes.js`** (pur, **testé**) : `matchDeepLink(read)` mappe les query
  params vers une URL de page interne (priorité `code_pj`, repli legacy `projet_id`/`code_chapeau`).
- **`src/api/fiche.js` → `getProjetIdByCodePJ(code)`** : résout code PJ → GUID (`getAll` filtré
  sur `cr04e_codeprojet`, `top:1`, apostrophes échappées).
- **`src/lib/DeepLink.jsx`** : lecture params (player + repli URL local), **résolution async**,
  garde-fou anti-refresh (sessionStorage), **repli `/Accueil` + toast** si code PJ introuvable.
- **`src/pages/FicheDetail.jsx`** : ancres `id="section-…"` sur les 4 sections + **scroll**
  (+ surlignage) depuis `?section=`.

**Contrat des liens** (base = variable d'env `BaseAppUrl` par environnement) :

| Usage | Query params | Ouvre |
|---|---|---|
| DE (→ SAP) | `?code_pj=PJ4987&vue=de` | `CreerDE?projet_id=<guid>` |
| FL | `?code_pj=PJ4987&vue=fl&section=industriel` | `FicheDetail?id=<guid>&section=…` |

Sections valides : `supply_chain` · `industriel` · `commerce` · `synthese`.
⚠️ Le player Code App utilise le segment **`/app/`** (pas `/a/`) et l'URL porte déjà
`?tenantId=…` → coller nos params avec **`&`**.

## 🛡️ 4. Durcissement de l'envoi SAP d'une DE

**`src/api/flux.js`** : extraction de **`postFlowRaw`** (renvoie la `Response` **sans lever**
sur `!ok`) ; `postFlow` reste un wrapper qui lève → appelants inchangés. Nouvelle clé **`VERIF_DE`**.

**`CreerDE.handleSubmit` (DE)** — nouvel enchaînement :
1. **Poids net obligatoire** : `poids_net` ajouté aux champs requis → bouton « Envoyer vers SAP »
   **désactivé** tant qu'il est vide.
2. **VERIF_DE** (`{ "Numéro": codeChapeau }`) : `200` → on continue ; `400` → **stop**, « code déjà
   existant, demandez un nouveau » (rien n'est écrit).
3. Écriture `cr04e_projet` (+ `cr04e_divisionprojet`).
4. **Envoi SAP** : lecture de la réponse — `200` = succès ; `400` = erreur.
   - Sur **400** : le projet est **repassé en brouillon** (`de_brouillon`), `projet_id` conservé
     (retry = même ligne, pas de doublon), on **reste sur le formulaire**.

Le code chapeau envoyé (`Numéro` / `CodeChapeau`) = celui résolu par **VL** (« Demander mon code »)
ou **« Besoin d'un nouveau code »**.
