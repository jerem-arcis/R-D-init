## 1. 🐞 Bug SAP « NetWeight » (virgule décimale) — résolu

**Symptôme :** `400 BadRequest — ungültiger Wert '6,123'` à la création d'article SAP,
alors que l'app envoyait bien `"6.123"` (point). Postman passait, l'app non.

**Cause racine :** le connecteur **SAP OData de Power Automate** sérialise les
`Edm.Decimal` selon la **culture du run**, déduite de l'en-tête `Accept-Language`
de la requête déclenchante. Le navigateur (FR) envoie `Accept-Language: fr-FR` →
virgule décimale → SAP rejette. Confirmé : Postman avec `Accept-Language: fr-FR`
reproduit l'échec.

**Correctif :** `src/api/flux.js` — `postFlow` force `Accept-Language: en-US`.
→ voir mémoire projet [[sap-decimal-accept-language]].

*Reste à faire : rebuild + redéploiement de l'app pour que le fix prenne effet en prod.*

- **`docs/mapping-fl.html`** — version filtrable (statique).

  - compteurs par nature, recherche, filtre par vue SAP, « règles à coder » ;
  - colonne **« Dans ta page ? »** (✅ / ❌ / doublon / auto) ;
  - carte **Saisies** (réelles / en page / manquantes) et carte **Règles** (à coder / réutilisables) ;
  - bandeau **« Comment lire cette page »** (source + explication de chaque statut).

**Chiffres clés :** 151 champs = **51 saisies brutes** (→ ~**29 réelles** après retrait
des doublons/fausses saisies) + **34 règles** + 29 constantes + 21 calculs + 16 workflow.
Côté règles : **1 réutilisable** (classe valo, via `computeClasseValoDE/DS`), **33 à coder**.

**Verdict :** la vue FL ne doit contenir que les **saisies** (~29). Le reste (~84) est
du **code de génération** (constantes + règles + calculs) à écrire dans un futur
`triggerSapSendFL()`, sur le modèle de la DE (`computeHierarchieDE`, etc.).
