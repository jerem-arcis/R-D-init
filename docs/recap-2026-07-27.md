## 🎯 Besoin

Ajouter un bouton dans l'app qui génère un PDF reprenant toutes les infos de la
Fiche de Lancement papier (`914201.pdf`), mais dans un **style Boncolac** (violet,
cartes, dégradés, très lisible — inspiré du mail « Demande en attente de DL »).

---

## 🎨 Conception (maquette validée)

Itérations sur une maquette HTML avant de coder (`mockup-fl-pdf-1page.html`) :

- Réplique **embellie** de la FL papier, **1 seule page A4**.
- Décisions actées : rendu **HTML → html2canvas → jsPDF** (téléchargement 1 clic),
  bouton dans le **header de la fiche**, champs vides → **tiret « — »**, couleurs
  forcées à l'impression (`print-color-adjust: exact`), logo **en base64** (anti-CORS).
- Ajouts de champs demandés en revue : **Contrat-date**, **Fam. arrangement**,
  **Agrément / Couv. / Ancien ou art. similaire**, **Dont nb cartons cheminée**.

**Spec :** `docs/superpowers/specs/2026-07-27-export-pdf-fiche-lancement-design.md`.

---

## ⚠️ Découverte importante : l'app n'a pas toute la donnée du papier

Le PDF papier `914201` vient d'un système legacy (Excel/beCPG). Le modèle de données
de l'app (SAP/beCPG) **ne contient qu'une partie** de ces champs.

- ✅ Présents : libellés, marque, origine, EAN, durée de vie, ancien code, secteur,
  groupe marchandises, groupe stat., nomenclature, centre profit, dimensions/poids
  UVC & colis, dates, + **Qté/an** (depuis la **DE liée**).
- ❌ Absents (→ « — » sur une vraie fiche) : code racine, code logistique, tout le
  bloc **marketing** (Pays/CNUF/coeff/clés), **réseaux**, **familles** de classification,
  **définition produit**, **palettisation** (nb UC, cartons/couche, hauteurs, cheminée).
- ⚠️ Validations : l'app a **4 visas réels** (Supply Chain / Gestion Besoin / Industriel /
  Commerce) → utilisés à la place des « Directions » du papier (signé / refusé / en attente + date).

## 🐞 Corrections en cours de session

1. **Bouton introuvable** → il n'était que sur la « Vue complète » (`FicheDetailV2`) ;
   or l'ouverture d'une fiche arrive sur la « Vue par service » (`FicheDetail`).
   → Bouton ajouté sur **les 2 vues**.
2. **Pages blanches en trop** → la pagination se déclenchait au moindre dépassement.
   → Remplacée par un **ajustement « contain »** : tout est ramené sur **1 seule page**, centré.
3. **Rendu « moins dingue » sur vraie fiche** (trop de « — ») → **repli exemple** :
   si la fiche n'a pas ses champs clés (`libellé`, `marque`, `EAN carton`, `secteur`,
   dimensions UVC) → génère l'**exemple 914201 complet**, téléchargé **`FL-EXEMPLE.pdf`**.
   Sinon rendu réel → **`FL-<code_article>.pdf`**.

## 📋 Points ouverts / à décider

- **Seuil de repli exemple** : garder la bascule « exemple ↔ réel » (5 champs clés),
  ou **forcer toujours l'exemple** tant que la vraie donnée n'est pas branchée ?
- **Unités** : le gabarit affiche les libellés du papier (ml / kg / cm) ; le modèle app
  stocke en **mm / g / m³** → léger décalage de libellé sur une vraie fiche complète.
- **Définition produit** : laissée à « — » (pas de source).
- Champs sans source (marketing, palettisation, familles…) : ne seront réels que si la
  donnée est un jour branchée (Dataverse / `DeclinaisonLogistique`).
